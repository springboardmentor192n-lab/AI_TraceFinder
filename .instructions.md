# 🚀 AI TraceFinder Development Instructions

## Project Overview
AI TraceFinder is a state-of-the-art image forensics analysis tool that identifies source scanners/cameras and detects image tampering using ML, deep learning, and signal processing.

## Core Technologies
- **Backend**: Python 3.8+, Flask 2.3+
- **Frontend**: HTML5, CSS3, JavaScript (Vanilla)
- **ML Models**: TensorFlow/Keras, scikit-learn, OpenCV
- **Deployment**: GitHub, Netlify

---

## Development Standards

### 1. Backend Development (`/backend/`)
- Use Python type hints for all functions
- Follow PEP 8 style guide
- Assert robust error handling with try-except blocks
- Log errors with traceback for debugging
- CORS-enabled for frontend communication
- Maximum file size: 50MB

**Key Files**:
- `app.py` - Main Flask application
- `config.py` - Configuration management
- `image_forensics.py` - Core forensics engine
- `identification.py` - Scanner identification logic
- `preprocessing.py` - Image preprocessing pipeline

### 2. Frontend Development (`/frontend/`)
- Responsive design using CSS3 media queries
- Vanilla JavaScript (no frameworks)
- Async/await for API calls
- Real-time progress feedback
- Drag-and-drop file upload support
- Accessibility compliance (WCAG 2.1)

**Key Files**:
- `index.html` - Main interface
- `css/styles.css` - Styling
- `js/upload.js` - File upload logic
- `static/script.js` - Main application logic

### 3. Model Training (`/backend/train_model.py`)
- Extract forensic features from training dataset
- Train ML models on feature vectors
- Save models as `.pkl` and `.keras` formats
- Store class mappings for inference
- Validate accuracy before deployment

## Code Quality Requirements

### Error Handling
```python
# Always use try-except with specific exceptions
try:
    result = process_image(img_path)
except FileNotFoundError:
    return {"error": "File not found", "code": 404}
except Exception as e:
    logger.error(f"Unexpected error: {e}", exc_info=True)
    return {"error": "Internal error", "code": 500}
```

### API Response Format
```json
{
  "success": true,
  "data": {
    "scanner_id": "Canon_EOS_5D",
    "confidence": 0.92,
    "analysis": {...}
  },
  "error": null
}
```

### Logging
```python
import logging
logger = logging.getLogger(__name__)
logger.info(f"Processing image: {filename}")
logger.error(f"Error: {exception}", exc_info=True)
```

## Model Improvement Strategy

### 1. **Feature Engineering**
- Extract PRNU (Photo Response Non-Uniformity) signatures
- Analyze FFT (Fast Fourier Transform) patterns
- Calculate spatial frequency features
- Compute texture descriptors (LBP, GLCM)
- Extract statistical moments and entropy

### 2. **Ensemble Methods**
- Combine multiple ML models (Random Forest, SVM, Gradient Boosting)
- Weighted voting for final prediction
- Cross-validation for robust accuracy estimation

### 3. **Deep Learning Integration**
- Fine-tune pre-trained CNNs (ResNet50, MobileNet)
- Transfer learning from image classification models
- Use convolutional layers for spatial feature extraction

## Common Tasks

### Add New Scanner Model
1. Update `config.py` with scanner specifications
2. Add training data to `/data/`
3. Retrain ML model: `python backend/train_model.py`
4. Test with sample images
5. Update documentation

### Update API Endpoint
1. Create route in `app.py`
2. Implement logic in appropriate module
3. Add error handling and logging
4. Test with curl or Postman
5. Update API_DOCUMENTATION.md

### Deploy to Production
1. Test locally thoroughly
2. Commit to GitHub main branch
3. Netlify auto-deploys on push
4. Verify deployment on netlify.toml
5. Test in production

## Troubleshooting

### Model Not Loading
- Check file paths are absolute
- Verify `.pkl` and `.keras` files exist
- Check compatible scikit-learn/TensorFlow versions

### CORS Errors
- Verify CORS headers set in `app.py`
- Check frontend requests use correct API URL
- Test endpoint directly with curl

### Uploads Not Processing
- Check upload folder permissions
- Verify MAX_FILE_SIZE setting
- Check file format is allowed
- Review backend logs for specific errors
